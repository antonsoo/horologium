# Clock reliability verification — 2026-10-04

The source changes were checked from a separate clean checkout on Node
24.21.0 / npm 11.19.0. The production website was then verified on GitHub
Pages. No npm release was made; the source-library correction remains in
Unreleased.

## Reproduced failures

- `#jd=%E0%A4%A` threw `URI malformed` and rendered zero calendar cards.
- `#jd=2451545junk` was accepted as 1 January 2000 rather than rejected.
- From 31 January 2024 at noon, `+1m` produced 1 March at 22:33 UTC.
- Entering 31 February 2025 silently produced 3 March.
- A date change removed the open calendar explanation; a scrub input
  immediately reset its thumb to zero.
- The implementation wrote a Julian-day snapshot on live ticks, so a live
  link became a paused link. Coordinates affected no visible calculation.
- Once the seasonal readout was connected, adjacent-day daylight in eastern
  and western longitudes was incorrectly assigned to night watches.
- Actual mouse dragging in Firefox exposed a native final-value commit
  after pointerup; recentering now waits until the next animation frame.
- Exhaustively checking UTC minutes found year 0, minute 2 displayed as
  00:01. The readout now accounts for the precision of its Julian day.

The browser suite covers malformed links, invalid date recovery with Enter,
leap-day and BCE transitions, exact civil stepping, keyboard and actual
pointer scrubbing, date bounds, hash history, live reload, unfinished drafts,
retained explanation state and focus, location-dependent output, cancelled
and superseded location responses, unanswered requests, invalid coordinates,
service exceptions, private-link fallback, keyboard skip navigation,
light/dark layouts and horizontal overflow.

The seasonal tests verify ownership of computed sunrise/sunset intervals,
including longitude/date boundaries and polar conditions. They do not add
an independent sunrise accuracy oracle. Existing independent calendar and
astronomy fixtures continue to run in the full suite.
